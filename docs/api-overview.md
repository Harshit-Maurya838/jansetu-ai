# API Overview

Conventions for the Spring Boot REST API. The endpoints themselves are listed in each module doc under **API endpoints**.
The live contract is generated by springdoc-openapi:

- Swagger UI: <http://localhost:8080/swagger-ui.html>
- OpenAPI JSON: <http://localhost:8080/v3/api-docs>

## Basics

| Topic | Convention |
|---|---|
| Style | REST over HTTPS, JSON (`application/json; charset=utf-8`) |
| Base path | `/api/v1` (breaking changes → `/api/v2`, old version kept ≥ 6 months because field phones update slowly) |
| Resource names | plural kebab-case nouns: `/children`, `/growth-measurements`, `/health-cards` |
| Nested resources | only for strong ownership: `/children/{childId}/growth-measurements` |
| IDs | UUID v4 strings. **Clients may send their own `id` on create** (offline-created records) and the server keeps it |
| Field names | camelCase in JSON, snake_case in MySQL |
| Dates | `LocalDate` → `"2026-03-14"`. Instants → ISO-8601 UTC `"2026-03-14T05:30:00Z"`. The app shows IST |
| Numbers | weight in kg, height in cm, temperature in °C, money in INR (decimal, never float) |
| Enums | UPPER_SNAKE strings, e.g. `"MODERATE"` |
| Language | API returns codes, not sentences. The app translates (`en`, `hi`). Exception: server-generated PDF reports use the user's `preferredLanguage` |

## Authentication

```http
Authorization: Bearer <access-token>
```

- **Access token:** JWT (HS256), 15 min, claims `sub` (user id), `role`, `centreId`, `ngoId`.
- **Refresh token:** opaque random string, 30 days, stored **hashed** in `refresh_tokens`, rotated on every use, bound to a `deviceId`.
- Public endpoints: `GET /health`, `/auth/login`, `/auth/otp/**`, `/auth/refresh`, `/auth/password/forgot`, `/auth/password/reset`.
- Details: [Module 01](modules/01-authentication.md).

## Authorization

Every endpoint has `@PreAuthorize` with the roles listed in the module doc, plus data scoping (see [rbac-matrix.md](rbac-matrix.md#mapping-to-spring-security)).
**`ROLE_SUPER_ADMIN` is allowed on every endpoint**, so the module tables leave it out unless it is the *only* role allowed.

## Response envelope

All responses use [`ApiResponse<T>`](../backend/src/main/java/in/jansetu/common/response/ApiResponse.java):

```json
{
  "success": true,
  "data": { "id": "7d0c…", "childCode": "AWC0412-0031", "fullName": "…" },
  "timestamp": "2026-03-14T05:30:00Z"
}
```

### Errors

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Request validation failed",
    "path": "/api/v1/children/7d0c…/growth-measurements",
    "fieldErrors": [{ "field": "weightKg", "message": "must be between 0.5 and 40" }]
  },
  "timestamp": "2026-03-14T05:30:00Z"
}
```

| HTTP | `error.code` (examples) | When |
|---|---|---|
| 400 | `VALIDATION_FAILED` | Bean Validation failed. `fieldErrors` filled |
| 401 | — | Missing/expired/invalid token → app calls `/auth/refresh` once, then forces login |
| 403 | `FORBIDDEN` | Role not allowed |
| 404 | `NOT_FOUND` | Not found **or outside your data scope** (never reveal existence) |
| 409 | `DUPLICATE_SUSPECTED`, `VERSION_CONFLICT`, `ALREADY_EXISTS` | Duplicate detection, optimistic-lock conflict |
| 413 / 415 | `FILE_TOO_LARGE`, `UNSUPPORTED_MEDIA` | Photo uploads |
| 422 | `BUSINESS_RULE` | Valid shape, but a rule failed (e.g. vaccine given before minimum age) |
| 429 | `RATE_LIMITED` | OTP / login throttling |
| 500 | `INTERNAL_ERROR` | Never includes stack traces or record data |
| 501 | `NOT_IMPLEMENTED` | Phase-I stubs |

Error messages **never contain health data or personal data**.

## Pagination, filtering, sorting

```
GET /api/v1/children?page=0&size=20&sort=fullName,asc&status=ACTIVE&q=ram
```

- `page` is zero-based. `size` defaults to 20, max 100.
- Response `data` is a [`PageResponse`](../backend/src/main/java/in/jansetu/common/response/PageResponse.java):
  `{ "items": [...], "page": 0, "size": 20, "totalElements": 134, "totalPages": 7 }`
- `q` is a free-text search (name / code / guardian mobile, depending on the resource).
- Filters are plain query params named after the field.
- **Sync endpoints don't paginate by page.** They use `since` + `limit` cursors ([Module 16](modules/16-offline-sync.md)).

## Concurrency & idempotency

- Every synced resource returns `version`. `PUT`/`PATCH` must send it back, and a mismatch gives `409 VERSION_CONFLICT`.
- `POST` with a client-supplied `id` that already exists and has the same content returns `200` with the existing record, so offline retries are safe.
- `POST /sync/push` is idempotent per `opId`.

## Files & images

- Upload: `multipart/form-data`, field `file`, JPEG/PNG only, ≤ 5 MB (the app compresses to ~1280 px / ~300 KB first).
- Stored in object storage (TODO(team): GCS or S3), **never** served from a public URL. Downloads go through
  `GET /api/v1/files/{id}` with the same access checks as the parent record, or through short-lived signed URLs.

## Rate limits

| Endpoint | Limit |
|---|---|
| `/auth/otp/request` | 3 per mobile per 15 min, 10 per IP per hour |
| `/auth/login`, `/auth/otp/verify` | 5 failures → 15 min lockout |
| `/sos` | not rate limited (but deduplicated within 2 min, see [Module 10](modules/10-emergency-sos.md)) |
| others | 120 req/min per user. TODO(team): pick a library (Bucket4j) |

## Service-to-service: backend → ai-service

- Base URL `AI_SERVICE_URL`, header `X-API-Key: ${AI_SERVICE_API_KEY}`. Reachable only on the internal network.
- Endpoints: `GET /health`, `POST /v1/growth/zscores`, `POST /v1/malnutrition/predict`, `POST /v1/meal-image/analyze`, `POST /v1/elderly-risk/predict`.
- The backend sends **pseudonymous IDs and features only**: no names, phone numbers or addresses. See [ml-overview.md](ml-overview.md).
- Timeout 5 s. If the AI service fails, the main flow still succeeds and the prediction is retried later (AI is never on the critical path).
